# 权限管理设计评审

2026-10-11，源码基线ee27527。当前已读HTTP/session、directory_store、用量SQL、
预算服务、助手快照、菜单路由与架构/迁移/范围测试。

| 风险 | 结论 / 修订 |
| --- | --- |
| 只有菜单隐藏，Member直接API仍全域 | 统一功能门禁和实际数据scope，测试直达API/恶意ID/total |
| 团队管理员用父部门grant，泄漏其他团队 | 限定用户分支与整部门分支区分，父节点仅上下文 |
| 多角色的菜单与范围笛卡尔扩权 | 范围分支分别从有效角色级别/任命与同级成员关系派生 |
| 组织管理已有管理员入口重复 | 本页只改四角色菜单，不改账号角色/任命/组字段 |
| 预算scope过滤改变控制/存储 | 只读安全投影，限额/继承/写权限/APIM不变 |
| public或旧报表快照泄漏 | 快照记录scope，旧全域不对受限viewer直接显示，重算按当前scope |
| 全局配置/密钥/无映射Copilot被下放 | Owner-only固定锁定，不虚构跨源隔离 |
| 半配置、并发覆盖、缓存旧权限 | 完整矩阵CAS/审计/permission_revision，失败保留草稿，切用户清缓存 |
| 旧迁移或测试种子改写 | 追加018，不改001-017；新装与升级、幂等/失败回滚实际PostgreSQL验证 |
| 演示账号验收误认为生产Graph | 本地实账测试身份与隔离scope；线上现有Owner/只读，真实Graph不计验收 |
| 上线旧包安全回滚 | 保存兼容三包及018前备份，不能让不支持scope的旧包重新向Member开放 |

方案按用户明确约束实施，不需要另设范围勾选页。评审结论：可以实施，验收必须覆盖
上述权限旁路，不以矩阵UI保存成功或源码断言替代完整验证。发现无法映射业务数据时
fail-closed而不是授全域；Owner-only操作不因勾菜单获得委派。

## 实现复评

- 复用现有管理员任命和directory_scope列，没有增加范围编辑器或第二套角色配置。
- 只读预算投影重新汇总受限父节点，保留写入/继承/持久化与APIM准入。
- 目录列表过滤在total和分页之前；人员详情/编辑二次校验本人/管理员范围。
- API每请求读取策略，客户端30秒/focus刷新清缓存，冲突不会覆盖配置。
- 全局模型元数据和助手配置仍是共享只读依赖，不因取消“模型管理”菜单误封预算/
  助手/调用；这些资源没有人员明细且敏感写入继续Owner-only。
- Copilot自助预算请求保持原账号边界；无目录映射的全域数据仍按原接口保护拒绝。
- 018未应用时目录Member访问fail-closed，不通过缺表兼容恢复全域读取。
- 本地真实四角色账号与浏览器结果符合设计；真实Graph/付费调用未测试。

## 单菜单回归修正

2026-10-11用户发现普通用户已勾选治理菜单但页面403。根因是上一版把共享
executive-overview等接口绑定成单菜单专属，不是自动人员scope失败。
接口授权按消费页面依赖取并集，所有查询仍使用原DataAccessScope。新增六组
“仅开放一个菜单”的真实PostgreSQL/API测试，并对五个治理页面运行普通用户浏览器验收。
测试同时验证同部门其他用户和恶意user_id不越权、Owner配置拒绝、撤销后403。
主布局仅在组织管理菜单有权时查询目录capabilities，避免无权限后台请求噪音。
