## 2. 背景与目标

模型价格和上下文窗口目前需要人工维护，部署名称也可能不同于公开模型名称。新增默认公网定价来源，减少单模型录入工作，并通过一次批量操作维护模型价格。

四项核心目标：

1. 添加模型、编辑模型均增加“从公网同步定价”选项，作为没有已配置来源时的默认选项，自动带出上下文窗口和价格。
2. 模型管理页面右上角增加“同步定价”按钮。按照每个模型保存的来源同步；手动定价跳过；未配置来源使用默认公网来源。
3. 公网来源使用 [anomalyco/models.dev](https://github.com/anomalyco/models.dev)，通过其公开 API 获取数据。
4. 以模型名称为主要匹配依据，在规则无法确定时调用系统默认模型辅助判断；价格本身必须来自 models.dev，不由 AI 推测。

## 3. 现状与差距

| 范围 | 已核验现状 | 本功能差距 |
| --- | --- | --- |
| 添加弹窗，图 1 | `ModelPublicationDialog` 提交发布请求，提供上下文和四项手填价格 | 缺少价格来源、自动匹配和预填；发布链路没有携带价格来源配置 |
| 编辑弹窗，图 2 | 支持 `manual`、`azure_retail`、`anthropic`；已有来源选择、目录搜索和折扣 | 增加 `models_dev`，支持名称匹配与上下文预填；默认值不能覆盖已保存来源 |
| 管理页面，图 3 | 右上角已有添加入口；客户端已有 `syncPrices()`，但页面未接入同步按钮 | 增加批量入口、执行状态、结果汇总和逐模型失败原因 |
| 后端 | 已有 `POST /api/v1/model-management/price-sync` 和价格目录读取接口 | 新来源、未配置来源回退、AI 辅助匹配及预览接口 |
| 存储 | `managed_model` 保存计费单价；`managed_model_price` 保存来源、映射、列表价、同步状态 | 当前查询将无价格配置记录的模型视为 `manual`，无法表达新需求的默认行为 |
| 保护措施 | 已有折扣继承、20% 价格变动复核、`superseded` 并发保护 | 必须扩展而非绕过这些机制，尤其保护首次默认同步和用户同时修改配置 |

当前 OpenAPI 模型平台分片尚未描述现有价格目录和批量价格同步接口，实施时需要补齐合同，而不只增加运行时代码。

## 4. 范围与术语

### 4.1 价格来源

| 存储值 | 界面名称 | 批量行为 |
| --- | --- | --- |
| `models_dev` | 从公网同步定价 | 使用保存的 models.dev 映射；未建立映射时先匹配 |
| `manual` | 手工填写 | 完全跳过，不查目录、不调用 AI、不修改价格 |
| `azure_retail` | Azure 零售价 | 沿用 Azure 来源、部署形态、区域和折扣 |
| `anthropic` | Anthropic 列表价 | 沿用 Anthropic 来源、映射和折扣 |
| 未配置 | 默认使用从公网同步定价 | 按 `models_dev` 处理，不根据现有价格是否为空判断 |

“未配置”是没有持久化的来源选择，不等于“价格为空”，也不等于已经明确选择 `manual`。现有明确来源必须保留。

### 4.2 同步数据

- 单模型添加和编辑：上下文窗口、输入单价、输出单价、缓存读取单价、缓存写入单价。
- 批量同步：四项价格、来源映射和同步元数据；不修改上下文窗口。
- 价格单位统一为 `USD / 1M Tokens`；上下文窗口单位为 Tokens。
- 现有模型级折扣优先，未设置则继承连接折扣；没有折扣按原价处理。
- 公网数据是公开参考价，不保证等于 Azure 实际账单、区域报价、合同折扣或图像等专用计费价格。

### 4.3 本期不包含

- 定时自动同步、定时任务管理和通知订阅。
- 改造历史用量费用回算、账单结算或汇率系统。
- 从 AI 答案、网页搜索或第三方报价推导价格。
- 自动更改模型身份、路由、访问权限、默认模型或部署配置。
- 新建云资源、部署模型，或因价格同步自动发布 APIM Revision。
- 对现有四项 Token 价格无法表达的阶梯、音频等独立计费规则强行换算。

## 5. 功能需求

### FR-01 添加模型默认公网同步

1. 在图 1“价格与限制”区域增加来源选择，默认选中 `models_dev`。
2. 输入部署名称或上游模型 ID 后，结合显示名称进行匹配；空名称不发请求。
3. 名称稳定后自动请求预览，提供可主动重试的同步操作；不能每输入一个字符都调用 AI。
4. 确定匹配后填入上下文窗口和可用价格，展示目录模型、提供方及匹配方式。
5. 自动来源的价格字段作为计算结果展示；用户要直接修改价格须切换为手动。
6. 上下文窗口允许调整，以适应实际部署限制；不能把目录上限当作部署能力保证。
7. 切换手动后保留当前草稿值，后续自动响应不能再覆盖这些值。
8. 发布请求携带来源及映射；发布成功后这些配置必须持久化，供后续批量同步使用。
9. 未匹配、接口失败或数据不适用时不得填入虚构价格。聊天模型可显式确认暂不计价，或切换手动后继续；不得无提示发布成“已同步”。

### FR-02 编辑模型同步与默认行为

1. 图 2的价格来源中增加 `models_dev`，保留三种已有选项。
2. 已有来源优先，尤其手动模型打开编辑页后仍为手动，不自动切换来源。
3. 没有来源配置的模型默认显示公网同步，并保留现有价格直到获得有效结果。
4. 公网模式下优先展示已经保存的目录映射；仅映射缺失或用户主动重新匹配时调用匹配流程。
5. 预览只修改草稿，取消编辑不会修改数据库。
6. 本次确定匹配时自动带出上下文；已经由用户调整的上下文草稿须确认后才能覆盖。
7. 重开一个已经映射的模型时，不因后台刷新自动覆盖已有部署上下文。展示目录建议值，用户可通过同步操作采用。
8. 修改显示名称不改变模型身份，已保存映射不会因名称展示变化被静默替换。
9. 保存时服务端复核映射和价格来源，并计算实际价格，不盲信浏览器提交的数字。

### FR-03 管理页面批量同步

1. 图 3右上角、“添加模型”旁增加 `RefreshCw` 图标及“同步定价”按钮，仅模型页签显示。
2. 仅具有 Owner 写权限的用户可执行，服务端必须再次校验权限和请求来源。
3. 默认同步当前模型管理注册表范围内的全部已保存模型，不因搜索、列表筛选或模型禁用而缩小范围。
4. 仍在发布且未进入注册表的模型不参加；正在移除的模型不得被同步写入。
5. 每个模型按照自己的来源执行，不把所有模型强制改成公网来源。
6. 手动来源完全跳过；未配置来源按公网模式尝试。
7. 公网来源已有有效映射时直接查保存的引用，不能每次重新让 AI 选一个价格。
8. 单模型错误不阻止其他模型，整次目录不可用也不得改写相关模型。
9. 执行中禁止重复提交。完成后更新注册表和相关价格查询缓存，显示已更新、无变化、手动跳过、未匹配、歧义、来源失败、待复核及未执行等数量和详情。
10. 价格大幅变动沿用现有复核保护；“同步完成”不代表所有模型价格均已更新。
11. 达到执行时间或 AI 调用预算时，明确报告尚未执行的模型，不能算作成功或手动跳过。

### FR-04 公网来源与数据完整性

1. 后端从 `GET https://models.dev/api.json` 获取模型目录；前端只调用 Turnstile API。
2. 将 provider 和 model ID 共同作为价格条目标识。同一模型在不同提供方的价格不得混为一条。
3. 单模型上下文和价格来自同一个被选中的 provider/model 条目。
4. 缺失值保持未配置，明确 `0` 才表示免费；禁止将缺失缓存价格自动写为 `0`。
5. 缓存项未发布时可留空，沿用现有计费回退，并在结果中说明回退；不能称其为公网发布的缓存价格。
6. 输入和输出价格缺失、值非法或条目不适用时，不执行自动价格写入。
7. 若更新中某个可选价格缺失，保留已配置的该项，标识为部分字段同步；完全替换缺失项需用户明确确认。
8. 支持缓存和失败隔离；手动触发批量同步应尝试刷新所需来源，而不能仅重放六小时前的缓存。
9. 数据过期或本次刷新失败可以展示上次数据，但不得将其当作本次新价格落库。

### FR-05 名称匹配与默认模型辅助

1. 输入包含部署名称/上游 ID、显示名称、模型别名；以名称为主要证据，提供方、模型家族、版本和用途作为辅助证据。
2. 先做保守规范化和精确匹配，再做候选召回；仅在名称别名或候选歧义无法由规则确定时调用系统默认模型。
3. “系统默认模型”本期解释为模型管理中 `is_default=true` 的聊天模型，不等同于 FinOps Assistant 独立固定的模型配置。
4. AI 仅能从服务端提供的有限候选中选择或返回“不匹配”，不能自行构造 model ID、provider、价格或 URL。
5. 保留型号、版本、日期、`mini`、`pro`、`thinking` 等区别；不能只因属于同一家族而视为同一模型。
6. 提供方明确且有同模型报价时优先该提供方；缺少部署报价时可选择明确的原厂公开参考价，并标识“参考价，非当前部署报价”。
7. 不按最低价、接口顺序或 AI 单独给出的置信度自动选价。不能确定具体型号或提供方时要求人工确认。
8. 记录匹配方式、证据、目录条目、匹配所用默认模型和时间，能够说明价格从何而来。
9. 默认模型不存在、禁用、不可达或回答格式不合法时，保留精确匹配能力；无法确定的模型保持现状并报告原因。
10. 匹配调用必须走系统已有调用适配器及用量记录路径，不创建新连接、不更改默认模型、不附带用户聊天或业务数据。

## 6. 历史兼容与明确限制

当前 `managed_model_price` 无记录时会被查询投影成 `manual`。实施前必须让前后端看见“来源是否配置”，不能直接把所有 `manual` 改成公网。

兼容规则：

1. 已存在的 `manual` 配置记录保留为手动并跳过。
2. 已存在 Azure/Anthropic 配置保留不变。
3. 无来源记录按本次需求使用公网默认；已有价格本身不能证明来源已经配置。
4. 新版显式保存手动模式时，即使价格全部为空，也必须保存手动来源记录。
5. 部分旧版创建路径可能把手动默认值省略成无记录。仅凭当前库不能还原当时是否主动选择了手动，不能声称能够无损识别这类意图。
6. 上线前展示受影响清单并允许这些模型显式保存为手动。首次公网价格和已有实际价格差异过大时，进入待复核，不直接覆盖。
7. 单纯打开或取消弹窗，不触发来源迁移或数据库写入。

## 7. 非功能需求

| 编号 | 要求 |
| --- | --- |
| NFR-01 | 公网请求设置超时、响应大小限制、结构校验；一个坏条目不影响有效条目 |
| NFR-02 | 同一次批量执行复用目录快照、候选索引和已解析匹配，避免每模型下载整个目录 |

| NFR-05 | 价格、来源映射和接受基准原子更新；失败不能留下价格与来源不一致的状态 |
| NFR-06 | 使用现有认证、写来源校验、结构化错误和国际化体系 |

## 8. 验收标准

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AC-01 | 新增模型输入可确定的目录名称 | 默认公网，自动填入上下文和已发布价格，展示 provider/model |
| AC-02 | 保存新增并完成网关发布 | 来源、引用和价格基准可重新读取，下次批量沿用同一条目 |
| AC-03 | 打开已保存的手动模型 | 仍选中手动，不请求目录或 AI，不覆盖任何字段 |
| AC-04 | 编辑未配置来源但已有价格的模型 | 默认公网，未匹配时保留旧值，取消后数据库不变 |
| AC-05 | 草稿切到手动时旧同步响应才返回 | 不覆盖手动草稿 |
| AC-06 | 公网缓存写入字段缺失，缓存读取明确为零 | 写入价保持空或保留原值；读取价可写 `0`，两者不混淆 |
| AC-07 | 混合公网、Azure、Anthropic、手动、未配置模型执行批量 | 各走各的来源，手动跳过，未配置走公网 |
| AC-08 | 搜索只显示一个模型后点击批量 | 仍同步注册表范围内全部模型，页面明确展示实际总数 |
| AC-09 | 同一模型存在多个提供方不同价格 | 不自动选择最低价；按确定提供方或原厂参考规则处理，仍歧义则人工确认 |
| AC-10 | 部署别名仅能经 AI 判定 | 调用当前系统默认模型，仅接受候选内且通过型号校验的结果 |
| AC-11 | 默认模型不可用或 AI 返回候选外 ID | 不写价格；精确匹配模型仍能完成同步 |
| AC-12 | 公网请求超时或数据非法 | 保留价格，报告来源失败；不以缓存旧值冒充本次成功 |
| AC-13 | 大幅价格变化，连续点击两次同步 | 两次均待复核，第二次不会因为基准被提前移动而自动接受 |
| AC-14 | 同步期间模型被改为手动、改折扣或删除 | 原计划作废，不覆盖新配置、不重建已删除模型 |
| AC-15 | 批量同步完成 | 上下文、模型身份、路由、默认配置和访问权限保持不变 |
| AC-16 | 图片模型或阶梯价无法表达 | 支持 GPT Image 的文字输入、缓存文字与图像输出 Token 价；其他用途或单位无法表达时保留原值，不把普通文本价用作图像输出价 |
| AC-17 | 无价模型和来源无法确定 | 不产生“免费”价格；用户可明确选择手动或暂不计价 |
| AC-18 | 非 Owner 调用批量或 AI 预览 | 服务端拒绝，前端按钮不可执行 |
| AC-19 | AI 调用预算/整次执行时间耗尽 | 返回未执行数量和逐项原因，允许重试，不静默丢项 |
| AC-20 | 重复执行且所有数值未变化 | 报告“无变化”，不把全部成功接受条目算成价格变更 |

## 9. 评审关注点

以下为本方案采用的默认决策，评审可调整，不阻止文档完成：

- 系统默认模型取模型管理的默认聊天模型，而不是 Assistant 的独立模型固定设置。
- 没有当前提供方报价时允许明确标记的原厂参考价；无法证明原厂型号时不自动接受。
- 批量只更新价格；上下文仅在单模型操作中带出。
- 特殊计费模型保留手动路径，只有单位、用途和字段语义均适配时才允许公网自动价。
- 延续现有 20% 价格变动复核保护，并覆盖无列表价基准的首次默认同步。
