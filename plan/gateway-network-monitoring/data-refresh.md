# 统一页面数据刷新

## 需求与边界

修复预算管理停留时不自动更新的问题，避免业务页面各自使用 10 秒、5 分钟或无轮询。系统配置 / 偏好设置提供统一周期。

本次仅改变前端只读查询调度，不改变原始 Token、业务归因、预算、APIM 策略、Event Hub 采集或定时对账。此前发现的 492 Tokens 汇总归因问题不在本次范围。页面不刷新不影响请求进入网关时的额度判断。

## 承载分析与选项

2026-10-12 线上只读检查：PostgreSQL Standard_B1ms 突发型，32 GB / 120 IOPS，API 与数据库都在 Southeast Asia。上海时间 06:09-12:09 的五分钟监控桶中，CPU 平均 9.3%、最高 26.1%，内存平均 54.2%，连接数最高 20，没有连接失败。少量普通读取的 HTTP 响应中位数约 133-285 ms，包含网络时间；不是纯 SQL 时间或并发压测。

当前低流量有余量，但预算 API 还包含多表/视图与范围查询，Repository 默认最多 4 个池连接，Functions 也使用数据库。不能据此承诺大量浏览器同时一分钟刷新安全。草案预算周期读取还带出整个目录导航；最终方案排除参考数据的周期重读。

| 选项 | 适用场景 | 理由 |
| --- | --- | --- |
| 近实时（1 分钟） | 调用排查、短期监控 | 最快可选，不是推送，不保证后台事件在一分钟内完成 |
| 5 分钟（默认、推荐） | 日常运营与预算查看 | 同等查询数下，轮询量是一分钟档的 1/5，兼顾显示新鲜度与突发型数据库负载 |
| 15 分钟 | 常规统计查看 | 低于高频监控负载，补足中间档位 |
| 30 分钟 | 低频查看 | 不追踪最新调用 |
| 1 小时 | 报表与趋势查看 | 降低重复查询 |
| 关闭定时刷新 | 按需查看 | 打开或切换页面更新一次；停留、后台切回不自动刷新；手动刷新始终可用 |

不提供 12/24 小时：对预算、异常、请求监控容易产生长期旧数据显示，关闭定时刷新的语义更明确。流式请求、Event Hub、后台对账与 Copilot 上游周期仍独立决定最终数据新鲜度。

## 架构设计

- 沿用现有显示偏好的浏览器级架构，不新增全租户配置或数据库迁移。版本化 localStorage 保存设置，同源标签页通过 storage 事件同步；无存储能力仍在当前会话生效并提示。空值/无效值/已移除的长周期回退到 5 分钟，数值 0 明确表示关闭。
- `DataRefreshProvider` 在认证门之后、共享 QueryClient 内，仅在登录期间运行一个调度器；修改设置立即重新读取当前动态业务查询并重置周期。关闭时不注册刷新计时器、可见性或焦点监听。
- 调度器对当前已挂载、已启用且不在请求中的业务查询调用 `refetchQueries(type=active, cancelRefetch=false)`。预算总览和人员、管理总览、四个监控页面、个人用量、订阅、Copilot、报表目录等共享周期。不请求未打开页面或未启用查询；有写入进行中时不发起新的周期读取，不触发模型调用。
- 目录导航、筛选项、图表图例用模型目录、下载配置、后端池元数据保持原缓存 TTL 和变更失效机制，不随预算轮询反复读取整个组织树。组织管理页的组织/单位/人员/审计表格仍按周期读取；模型管理和负载均衡的主目录明确 opt-in，不影响目录作为其他页面参考数据时的缓存。
- 页面挂载重新查询，不受缓存 staleTime 抑制；共享 APIM/Copilot 页面组件按页面身份挂载，保证关闭定时刷新后切换页面也重新读取。手动刷新保留原逻辑。
- 自动刷新开启时隐藏标签页暂停；恢复时仅当周期到期才补一次，不补发所有漏过周期。关闭时后台切回不补刷新。切换频率、注销、组件销毁清理计时器，不叠加或取消进行中的请求。
- 权限能力检查、会话验证、2 秒发布进度、3 秒目录同步进度独立运行，不受显示周期影响。发布数据已经在进度轮询时不重复调度。权限和 Copilot 配置编辑读取会初始化草稿，通过 meta 退出周期刷新，避免丢失未保存内容；助手会话流不参加周期读取。
- 移除业务页面硬编码的 10 秒和侧栏 5 分钟计时器；请求追踪的提示显示实际选项，不再写死 10 秒。

## 验证方法

虚拟时钟覆盖全部周期、隐藏/恢复、关闭、频率切换和销毁；真实 QueryClient/QueryObserver 验证预算/人员/监控统一读取，静态参考数据不轮询，主目录 opt-in，禁用/未挂载/进行中查询不重复请求，以及关闭模式下缓存页面再次挂载与手动更新。

浏览器检查中文/英文选项、持久化、跨页提示，实际一分钟预算查询且不重复读取组织树，以及关闭后停留无业务轮询、重新进入更新和手动刷新。长周期不在生产等待实测，以虚拟时钟验证。不发起额外模型调用，不修改线上数据或配置。
