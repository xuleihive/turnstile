# 下载布局与角色下载权限

本文件维护权限和布局契约。用户版当月个人预算下载门槛见 [有效需求](requirements.md#1-双版本与下载权限)，
它与本文件的角色下载权限叠加判断。下文测试数字均属于标注日期的历史验证，不是本次回归结果。

## 范围与默认行为

- 下载页在足够宽的桌面区域并排显示用户版/订阅版，窄屏自动单列；仅一个版本获授权时居中单列。
  移除“订阅版导入 magpie”说明模块，保留凭据风险确认、默认订阅和模型信息。
- 权限页分为菜单管理、下载权限两部分，主区域及各模块子项目可以折叠。
  默认折叠菜单模块子项，展开下载的两个权限项，使两大部分在首屏可识别。
  折叠不改变权限；搜索覆盖两种权限，批量勾选仅影响匹配的可配置项目。
- 两个动作 ID 为 `user-plugin`、`subscription-plugin`，不作为菜单 ID，也不作为模型或数据 scope。
  沿用 user / team_admin / department_admin / organization_admin 四组、多组并集和 Owner 固定全权。
- 新迁移的默认值保留旧行为：四组用户版均可下载，订阅版默认仅 Owner 可下载。
  Owner 可明确委派订阅版下载；Member 只可导出本人拥有的应用，匹配当前账号 ID、邮箱或受信治理用户 ID。
  不借管理员角色推导其他应用的密钥访问权，不导出系统订阅、无效状态或其他网关的 Key。
- 数据库模式下，订阅版委派还要求关联有效人员。用户版保留已有人员、模型目录和默认订阅验证。
  legacy 模式保持旧下载行为，下载矩阵只读；服务端拒绝此模式的下载授权写入，避免保存不生效的策略。
  下载权限不撤销已安装客户端授权，不替代 APIM 身份验证、模型权限或预算控制。

## 保存与鉴权

- `020_plugin_download_permissions` 仅给 permission_policy 追加 download_groups JSONB。
  001-019 校验和、既有菜单配置及 revision、审计、会话、原始预算/用量不重写。
- Owner GET 返回 download_groups 与 download_catalog；PUT 可同时提交菜单和下载两种四组矩阵。
  共用 expected_revision/CAS、同一事务和目录 permission_revision；等价保存不增加 revision。
  新审计 JSON 使用 version=2、groups、download_groups；既有审计记录保留原格式。
- 菜单旧客户端不提交 download_groups 时保留当前值，不重新启用已撤销下载权限。
  缺组、重复或未知动作、未知角色拒绝；Owner-only 菜单仍不可委派。
- 当前会话和登录 Profile 返回 download_permissions，每次请求从当前目录角色及策略解析。
  用户版、订阅版的 options 和 POST 下载端点均检查权限，服务层再次检查；拒绝先于 Key 读取及 grant 创建。
  保存策略后，已有会话在下次请求即采用新策略，不要求重新登录。
- 前端分别隐藏未授权卡片并禁用对应查询；两版都无权时隐藏下载菜单及搜索入口，直接 URL 使用已有安全页面回退。
  权限修订进入查询 key，Profile 权限变化清理旧缓存，下载进行中变更权限则中止前端下载。
- 订阅版授权不开放原有订阅管理/密钥读取与轮换 API，也不开放权限管理、系统设置或预算写入。

## 下载页视觉对齐（2026-10-14）

- 依据 `plan/user-settings/design.md` 的平台视觉规范，以及现有用户设置/模型管理工作区实现：
  桌面保留 56px 顶部标题区、14px 标题，正文 12-14px、辅助信息 11-12px，使用既有语义色，卡片圆角 8px。
- 去除正文重复的 AIGateway-Proxy 标题和介绍，只保留顶部「下载客户端」及官方客户端下载入口。
  正文直接展示用户版和订阅版卡片，不恢复已移除的订阅版导入说明模块。
- 两版卡片分为标题/版本、信息/配置、凭据确认/下载三个区域。个人信息使用只读属性行，
  安装步骤和文生图说明分段；版本复用 Badge。凭据提示与确认始终可见，不折叠安全信息。
- 桌面客户端下载按钮、插件下载按钮和选择框统一为 32px 高；窄屏/触屏至少 44px，
  移动选择框保留 16px 字号以避免 iOS 自动放大。继续使用黑色主按钮及深色主题高对比配色。
- 两版操作区在桌面底部对齐；应用订阅占满一行，网关与密钥在下一行。长名称可换行或通过
  原生选择框 title 读取完整值。奇数模型项占满末行，不留下灰色空单元格。
- 保留授权可见性、独立勾选、选择订阅后清除确认、下载中禁用和错误状态；不改查询、API、
  下载参数、用户默认订阅或插件包内容。本节为前端样式调整，不新增迁移或改变共享 Core。
- 新增文案同步英文、日文及韩文。验证桌面/手机、浅色/深色、长名称、仅用户版、空目录和
  请求失败场景；本地安装包和目录为无凭据测试件，不在该轮操作生产环境。
- 本轮本地验证：255 项 JavaScript 测试、TypeScript/Vite 构建通过；Playwright 覆盖中/英/日/韩
  及 1440/1280/390/320px 视口，确认独立勾选、选择订阅后重置确认、双版 ZIP 下载、键盘操作、
  按钮尺寸/对齐和无横向溢出。授权页保留原有布局规则。
- 2026-10-14 的发布和数据库恢复细节已合并至 [历史发布索引](release-history.md)，
  不把当时的数据库状态或发布阶段作为当前操作依据。

## 本地验收与上线边界

- PostgreSQL 覆盖追加迁移、历史与校验和保留、幂等重跑、四组校验、多角色并集、CAS冲突、旧客户端兼容、会话撤权。
- API 覆盖拒绝时不创建 grant/不读取 Key、委派仅匹配本人应用、伪造其他订阅返回 404、权限撤销后返回 403。
- 浏览器使用隔离的真实本地 PostgreSQL/会话和权限 GET/PUT；下载元数据及 ZIP 使用无凭据测试件拦截。
  不调用模型，不访问生产管理环境。桌面 1440x1000、移动 390x844，验证双列/单列、折叠键盘操作、独立可见性、
  隐藏版本不发请求、原子保存、冲突保留草稿，以及页面无错误和横向溢出。
- Browser 插件未提供，使用已有 bundled Playwright。验收脚本与截图在 Git 外保存，临时数据库/HTTP桥接/浏览器退出时清理。
- 发布前本地验证：全量 Python 1903 passed / 7 skipped，最终增量 Python 55 passed，插件 JS 46 passed；
  Ruff、Mypy（157 个源文件）、前端 TypeScript/Vite 构建及浏览器验收通过。保留已有 Starlette 与大 chunk 提示。
- 此修改改变共享 Core，禁止复用旧的 API-only 发布脚本；上线状态以单独的发布验收记录为准。
  后续须先备份及迁移 020，再协调 API、Telemetry、Control-plane 的源码、运行 manifest、预期 Core 摘要及既有状态。
  不修改 APIM 策略或重建基础设施；迁移使用既有 backend.migrate 入口。
- 安全回滚不能把新的下载禁用策略交给不识别它的旧 API；应保持相关下载端点关闭或使用兼容修复包。
