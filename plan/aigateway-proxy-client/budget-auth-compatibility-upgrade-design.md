# 客户端鉴权与 Token/USD 预算设计

维护基线：2026-10-18。本文件描述当前实现，不再保留升级前快照、拟议接口或阶段待办。
安装与恢复入口见[预算运维手册](operations.md)；
本轮线上观察时间、目标预算与验收边界只记录在 [USD 验收记录](usd-installation.md)。

## 身份与兼容边界

用户登录、组织目录和服务器间信任是三个独立维度：

| 维度 | 当前实现 | 边界 |
| --- | --- | --- |
| 用户登录 | 平台密码或 Entra SSO，沿用账号、会话及客户端 grant | 密码用户不需要迁移到 Entra |
| 组织人员 | 数据库目录；Entra/Graph 同步独立配置 | SSO 成功不代表目录同步、账号绑定或模型授权成功 |
| 后端委托 | 复用运行时的目标校验、受信身份、托管身份令牌缓存 | APIM 验证 tenant、audience、client/object 白名单；最终用户不必属于该租户 |

沿用 `governance_user_id`、`effective_user_id` 及当前成员关系，不因同名或未验证邮箱合并身份，
不替换历史治理标识。未安装执行协议时保留旧 Token 上下文兼容；不能为了清理代码删除旧安装的认证入口。

```text
密码 / SSO -> 既有客户端 grant -> 账号与目录人员
                                  |
                     订阅、模型、协议、发布路由检查
                                  |
                 原生代理 + 共享后端委托 -> APIM
                                  |
                   个人及适用应用准入 -> 模型调用
                                  |
                 APIM / Observer -> 正式用量 -> 结算
```

控制台与原生代理共用可信委托，不将原生代理替换为控制台结构化调用 DTO。
连接池按应用生命周期复用，凭据和个人身份逐请求写入，不接受上游 Cookie，保留原生 SSE、工具和请求正文。
Agent、会话和轮次是白名单追踪字段，不是鉴权依据。组织、人员、订阅、请求关联和委托头由服务器确认。
受信中文元数据沿用显式 `percent-v1` 编码，仅解码一次；Key 和令牌不参与编码。

默认订阅与密钥规则见[插件设计](design.md#默认订阅与身份)。不按显示名或排序选订阅，
不回退到 master、probe 或其他用户的订阅，不修改客户端源码或用户 Agent 配置。

## 预算与金额契约

- 组织树按 UTC 月份使用 Token 或 USD；不同组织可在同一 APIM 上共存。
- 组织、部门、个人沿用既有层级分配约束；组织/部门行不是新增的实时共享 S/A 额度池。
- 实际准入检查个人和适用的应用 scope；应用是独立维度，两者单位可以不同，不能相加。
- 团队与附加成员只影响既有筛选和权限，不新建计费 scope，不将一个人重复计费。
- 部门 `audit/block`、应用 `enforce` 与单位分开；曲线可见性不授权改变平台阻断策略。
- 金额使用 `NUMERIC(30,14)` / Decimal，权威 API 金额是十进制字符串。
- 请求固定不可变价格快照，覆盖输入、输出、缓存读写及适用阶梯；调价不重算既有请求。
- 已确认、预留和保守占用分开；未知费用不等于零，HTTP 错误或超时不证明免费。
- 组织或部门有预算不自动创建个人金额；用户版下载仍要求本人已配置当月预算。

单位切换复用 `BudgetRecoveryService.policies()` 的 quiesce、排空、旧单位对账和新单位期初验证。
不能直接改 Table 的单位，也不能把数据库保存成功视为网关策略已同步。
部门编辑资格通过 `budgetLimit(organization) != null` 判断，兼容 Token/USD 和已配置的零额度。

## 能力 API 与客户端显示

`GET /api/v1/budgets/capabilities` 已实现，要求认证及预算范围访问，返回 `Cache-Control: no-store`。
响应为 `token_available`、`usd_available`、`reason_code`、`message`。
源码入口为 `backend/services/budget_readiness.py`，核对执行开关、当前周期 rollout、目标、
委托配置、有效发布、epoch 和已验证模型计数契约；不会在打开表单时扫描 ARM。
它不是完整云端安装证明，预算保存、准入及激活仍执行各自权威检查。

USD 未就绪时禁用选项并展示原因；后台 503 保护保留。依赖恢复后重新读取能力，不能假造 ready。
Owner 原生目录及执行验证接口的职责和费用边界见[配置手册](operations.md#budget-verification)。

用户版 USD 用量返回 `quota_contract_version=2`，`budget` 中包含：

| 字段 | 含义 |
| --- | --- |
| `mode`、`currency`、`period` | `usd`、`USD`、UTC 预算月份 |
| `limit`、`confirmed` | 精确上限、已结算金额 |
| `reserved`、`upper_bound` | 活动预留、保守占用 |
| `available` | 上限减三类占用，最低为零 |
| `enforce`、`ledger_version` | 平台执行策略与账本版本 |

宿主标准窗口的浮点数仅用于展示，不用于财务运算。金额窗口要求可验证且已同步的执行余额，
未初始化、单位不匹配或策略待同步返回 503，不伪造零消费。
Token 契约保持兼容，不对 USD 的 `token_limit=NULL` 使用整数转换。

插件本地控制、平台强制策略、按单位分段的真实采样及原生曲线规则见
[图标与本地控制](plugin-icons-toggle-design.md)。没有宿主历史时不补造采样，不能跨单位解释旧曲线。

## 安装、迁移和工具边界

- 复用完整现有迁移链，本轮不新增或改写 SQL 迁移。已应用文件的名称、校验和及历史消费不可变。
- 启动保持 `backend.migrate -> backend.bootstrap -> API`，迁移失败阻止启动，bootstrap 不重置已有 Owner。
- 常规发布不自动创建 rollout、初始化余额、启用 USD 或覆盖 APIM 策略。
- 既有安装先验证全部可达修订的共享 paused fence，再排空并保留期初；每 scope 只初始化一次。
- SQL 协调状态 active 不等于网关准入 active；真实请求、账本和结算通过后才激活共享 fence。
- schema-one 兼容模板与离线升级工具仍用于其他旧安装，不因本环境已升级而删除。
- 安装、接管及激活工具是通用操作库，不是自动云部署 CLI；实际入口与限制见
  [预算运维手册](operations.md#supported-tools)。

Observer 独立镜像只包含允许的运行文件和标准库协议模块，不依赖 API 的 Pydantic 模块。
JSON 用量支持 MIME 参数和大小写；Grok 推理计数仅在总量精确证明未包含于 completion 时加入输出，
标准接口已含推理时不重复计数；不守恒的计数继续未验证。
诊断推理复用正常模型超时，而非额外的八秒短超时。

## 恢复与维护约束

任何 APIM 修改先备份运行包、数据库、账本、相关策略/修订、配置、身份与秘密，秘密只保留私有密文。
精确 ETag、fresh readback、资源白名单、不可变 journal 和原有发布依赖校验不能作为“临时代码”删除。
未知外部写入只读恢复原 intent，不重发未知付费请求、不改旧时间戳或原始证据。
已有金融消费后优先前向修复；恢复旧余额、单独回退消息检查点、关闭开关或切旧修订均不是安全回滚。

已完成核心验收不代表所有个人 USD、流式、并发、性能及灾难恢复矩阵均已完成。
未纳入本轮的通用新装/升级入口历史问题见[维护边界](release-history.md#未纳入本轮的历史问题)。
本轮具体观察和费用边界只引用 [USD 验收记录](usd-installation.md)，不在多个文件复制动态状态。
